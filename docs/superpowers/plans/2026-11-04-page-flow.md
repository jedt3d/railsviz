# RailsVis Page Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `pages` and a `layouts` section to `data.json` (schema 3) and a "Page flow" view that draws the app's pages as a Mermaid flowchart with the links, forms and redirects Rails conventions make explicit, every node and edge linked to a file and line.

**Architecture:** A `Templates` module resolves templates, layouts and partials through a controller's own view paths and compiles a template to Ruby with the handler Rails registered for its extension. A `ViewScan` reads one Ruby source with Prism and keeps route-helper calls (with receiver, form flag, redirect flag, enclosing `def`), partial names and view-component constants. The `Pages` collector joins the two over the controllers' rows and emits the rows the spec's section 4.2 shapes; `Dump` wires it in after `controllers`. The viewer builds a graph from `pages`, `layouts`, `routes` and `controllers`, renders it with the vendored Mermaid, then attaches hover, click and keyboard behaviour to the rendered SVG, with the selection kept out of `hashchange`.

**Tech Stack:** Ruby ≥ 3.3, Rails 8.0–8.1 (`ActionView::LookupContext`, `ActionView::Template.registered_template_handler`, `AbstractController::Layouts#_layout`), Prism (in the bundle through Rails), Minitest, vanilla JS viewer with vendored Mermaid 12.2.0 at `securityLevel: "strict"`.

**Spec:** `docs/superpowers/specs/2026-11-04-page-flow-design.md` (all sections; section 9 is decided: scaffold forms and redirects that take a record are left out).

## Global Constraints

- Gem runtime dependency stays `rails ">= 8.0", "< 8.2"` only; no new gem, no new vendored viewer bytes (spec G4).
- `data.json` top-level keys become exactly `meta, documents, routes, controllers, models, databases, boot, middleware, entry_points, gems, pages, layouts, warnings`; `meta.schema_version` becomes the integer `3`. The existing eleven keys keep their shapes; the `view` field on actions keeps `kind`, `path`, `url` (spec 4.1, 4.2).
- Every code node is `{ "name", "path", "line", "url" }` from `RailsVis::Source.node` / `for_const` / `for_method`; a template outside app code is kept with `path: nil, url: <gem url or nil>` (spec 4.1). Never a hand-built node.
- A failure on one node is a warning `{ "where" => "pages", "message" }` via `RailsVis::Collectors.warning` / `.error`; the whole collector raising yields `{ "pages" => [], "layouts" => [] }` plus one warning (`Dump#run`, spec 4.3).
- Nothing is guessed: a helper call with an unknown receiver, or a stem that is not a route name in its engine, is dropped without a warning (spec 4.2, 7). No record-based forms or redirects (spec 9).
- Viewer: vanilla JS in `viewer/src/app.js`, styles in `viewer/src/app.css` only through tokens in `viewer/src/tokens.css` (no colour or font literal, also inside Mermaid `classDef`: style Mermaid nodes from CSS); icons are symbols in `viewer/src/index.html`; after any viewer change run `ruby script/build_viewer.rb` and commit `viewer/index.html`; `node ~/.claude/skills/hallmark/scripts/sloplint.mjs viewer/src --genre editorial --scope app` stays at 0 FAIL / 0 WARN (the three existing waivers stay).
- The selection never assigns `location.hash`; it uses `history.replaceState` (spec 5.4).
- Tests: `bundle exec rake test` stays green on SQLite; fixtures live only under `test/dummy`.
- Commits: write the message to a file in the scratchpad and use `git commit -F <file>` (CLAUDE.md: never `$(cat …)`); end the message with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. The `# "..."` after each commit command below is the message's first line.

## Review Focus

- A layout template's `<%= yield %>` is a Prism error at the top level: compiled template source must be parsed inside a method body, and the development-mode filename annotation (`ActionView::Base.annotate_rendered_view_with_filenames`) must be off while compiling or every line is off by one. - A partial that renders itself, or two partials that render each other, must not loop the collector. Test in Task 3.

**Interfaces:**
- Produces `RailsVis::ViewScan.new(source, path:)`, parses once; attributes:
  - `error -> String | nil`: the first Prism error message (`"#{path}: #{message} (line N)"`), nil when clean. A scan with an error still exposes whatever it found.
  - `helpers -> Array<Hash>`: one per `CallNode` whose name matches `/\A(\w+)_(path|url)\z/`, in source order:
    `{ "stem" => "new_patient", "name" => "new_patient_path", "receiver" => nil | "main_app" | "<proxy name>" | :other, "line" => Integer, "form" => true/false, "method" => "patch" | nil, "redirect" => true/false, "def" => "create" | nil }`.
    `receiver` is `nil` for no receiver, the method name as a String when the receiver is a `CallNode` with no receiver and no arguments (`main_app`, `spina`, also `foo`: the collector decides which names are engines), `:other` for anything else (`@x`, `self`, a constant, a chained call); the collector drops those. `form` is true when the call sits anywhere inside the arguments of `form_with`, `form_for`, `form_tag`, `button_to`, or a `link_to` whose keyword-hash arguments contain `method:` or `data: { turbo_method: }`; `method` is that literal's symbol/string downcased when present (`button_to` without one → nil). `redirect` is true when the call sits anywhere inside the arguments of `redirect_to`. `def` is the innermost enclosing `DefNode` name as a String, nil outside any def (template bodies are wrapped by `Templates.compile` in `_rails_vis_template`, so report nil for that name).
  - `partials -> Array<String>`: unique names from `render "x"`, `render "dir/x"`, `render partial: "x"` with a String literal (first positional or the `partial:` pair). Anything else is ignored.
  - `components -> Array<String>`: unique constant names (`ConstantPathNode#full_name` / `ConstantReadNode#name`) from `render Const.new(...)` (first positional argument a `CallNode` named `new` whose receiver is a constant).

**Interfaces:**
- Consumes `Templates.find/layout/layout_name/partial/compile` (Task 1), `ViewScan` (Task 2), `Source.node/for_const`, `Collectors.warning/error`.
- Produces `RailsVis::Collectors::Pages.new(repo:, routes:, controllers:).call -> { "pages" => [...], "layouts" => [...], "warnings" => [...] }` with the row shapes of spec 4.2, plus two fields this plan adds:
  - page `"format"`: `"html"`, `"json"`, … (`template.format.to_s`) or `null` for an Inertia page; the viewer's node rule reads it.
  - link `"method"`: the explicit literal verb from `ViewScan` or `null`.
  Rows are sorted by `controller` then `action`; `layouts` by `name`. `template` for an Inertia action is the page node from the controllers row's `view` (`name` = basename, `line` 1). An action produces a row only when it has a template, links or redirects.
- Produces `RailsVis::Collectors::Pages.engine_of(file, candidates) -> String | nil` (module function): `candidates` is `[[engine name or nil, root]]`; returns the name of the candidate with the longest root that is a path prefix of `file` (`root + "/"`), nil when none matches.
- Engine attribution of a bare call: candidates are `[[nil, Rails.root.to_s]] + Rails::Engine.descendants.reject { |e| e <= Rails::Application }.map { |e| [e.name, e.root.to_s] }` (an engine whose `root` raises is skipped); the longest root that is a path prefix of the file wins. `main_app` → nil. A proxy name maps through `engine_name`; unknown names and `:other` receivers drop the call. A stem is kept only when `routes` has a row with that `name` and `engine`.
- Every `ViewScan` is built with `path: @repo.relative(file)`, so warnings and `source` nodes name repo-relative paths. A redirect's `source` is `Source.node(name: "#{controller}##{action}", path: <controller file>, line: <the helper call's line>, repo:)`. An Inertia action's `template` is `Source.node(name: File.basename(view["path"]), path: File.join(@repo.root.to_s, view["path"]), line: 1, repo:)` from the controllers row's `view`.
- Partials resolve recursively with a visited set keyed by `identifier`; each file is scanned once per dump (cache keyed by path). Components: `const.safe_constantize` → `Source.for_const`; the component's template is the sidecar `Dir.glob(path.sub(/\.rb\z/, ".*")).reject { |f| f.end_with?(".rb") }` compiled like any template, else the class file itself scanned as Ruby.
- Redirects: for each action row with a source line, the controller file's scan (as Ruby) filtered to `redirect: true` and `def == action`.
