# RailsVis Views 4 to 7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the four remaining views from the spec to the dump and the viewer: Boot and configuration (issue 17), Middleware stack (issue 18), Entry points (issue 19) and Gems (issue 20), so `data.json` carries every top-level key spec section 11 names and the dashboard shows them.

**Architecture:** Three new collectors (`Boot`, `Middleware` + `Gems`, `EntryPoints`) follow the existing collector shape: plain hashes, every code node through `RailsVis::Source`, a warning instead of an abort on any one bad node. `Dump` runs them after the existing five and bumps `meta.schema_version` to `2`. The viewer gains four navigation destinations and four views rendered from the embedded JSON alone, in the redesigned Ink system (tokens, tags by role, ruled tables, bars). Tasks 1 to 3 are independent and run in parallel; Task 4 (dump wiring and viewer) runs after they merge.

**Tech Stack:** Ruby ≥ 3.3, Rails 8.0–8.1 reflection (`Rails.application.initializers.tsort_each`, `Rails.application.middleware`, `Bundler.load.specs`, `Rails::Railtie.descendants`, `ActiveJob::Base`/`ActionMailer::Base`/`ActionCable::Channel::Base.descendants`, `Rake::Task.tasks`), Minitest, vanilla JS viewer.

**Spec:** `docs/superpowers/specs/2026-11-03-rails-onboarding-dashboard-design.md`, sections 6 (rows 4 to 7), 7, 8, 10 (Boot, Middleware, Jobs, Mailers, Channels, Rake tasks, Gems) and 11.

## Global Constraints

- Gem runtime dependency stays `rails ">= 8.0", "< 8.2"` only; standard library otherwise. No network access during a dump.
- `data.json` top-level keys become exactly `meta, documents, routes, controllers, models, databases, boot, middleware, entry_points, gems, warnings` (spec section 11); `meta.schema_version` becomes the integer `2`.
- Every code node is `{ "name", "path", "line", "url" }` built with `RailsVis::Source.node` / `for_const` / `for_method`; gem code gets `path: nil, line: nil` and a gem URL; never a hand-built node.
- "App code" means `RailsVis::Source.app_code?(path, repo:)`.
- Nothing that could hold a secret is written: no credential values (keys only, top level), no ENV values (keys and the file:line that reads them only), no database url/password/host/username, no middleware arguments, no recurring-task `args`.
- A failure on one node records a warning `{ "where", "message" }` via `RailsVis::Collectors.warning` / `.error` and continues; a collector that raises yields its empty shape and one warning (`Dump#run`).
- Viewer: vanilla JS in `viewer/src/app.js`, styles in `viewer/src/app.css` only through the tokens in `viewer/src/tokens.css` (no colour or font literal); after any change run `ruby script/build_viewer.rb` and commit `viewer/index.html`; `node <hallmark-dir>/scripts/sloplint.mjs viewer/src --genre editorial --scope app` must stay at 0 FAIL / 0 WARN (one waiver on 37 exists). Icons come from the sprite in `viewer/src/index.html` (add symbols there; never an emoji).
- Tests: `bundle exec rake test` stays green on SQLite; fixtures live only in `test/dummy`.
- Commits: `git commit -m "..."` with a literal message; never build a message with `$(cat …)`.
- Branch base: `main` at `bf01d55` or later; if your worktree's `main` is older, `git reset --hard bf01d55` first.

**Interfaces:**
- Produces: `RailsVis::Collectors::Boot.new(repo:).call -> { "boot" => Hash, "warnings" => [...] }` where the Hash is:
  - `"application"`: code node for the application class (`Source.for_const(Rails.application.class, repo:)`).
  - `"environments"`: array of code nodes, one per `config/environments/*.rb` in name order, `line` 1, `name` the file's basename without `.rb`.
  - `"initializer_files"`: array of code nodes for `config/initializers/*.rb` in Rails load order (each existent directory of `Rails.application.paths["config/initializers"]`, files sorted by name), `line` 1, `name` the basename without `.rb`.
  - `"app_initializers"`: `[{ "name" => "dummy_marker", "railtie" => "Dummy::Application", "source" => node }]` for every initializer from `Rails.application.initializers.tsort_each` whose `block.source_location` is app code, in tsort order; `railtie` is `initializer.context_class.name`.
  - `"framework_initializers"`: `[{ "railtie" => "ActiveRecord::Railtie", "count" => 27, "url" => gem URL or null }]` for the rest, grouped by `context_class.name`, in first-seen tsort order; `url` from `Source.gem_url(path, repo:)` of the block's file.
  - `"env_keys"`: `[{ "key" => "DATABASE_URL", "references" => [node, ...] }]` sorted by key; references are app code nodes (`name` = the key, `line` = the line) for every match of `/ENV(?:\.fetch\(|\[)\s*["']([A-Z][A-Z0-9_]*)["']/` across `Rails.root.join("config/**/*.{rb,yml,yaml,erb}")`; one reference per match, file order then line order.
  - `"credentials_keys"`: `Rails.application.credentials.config.keys.map(&:to_s).sort` when `Rails.application.credentials.key.present?` (rescue any error to the same null path), else `null` plus the warning `"credentials: no master key available; credential keys omitted (values are never collected)"`.
  - `"doc_url"`: `DocLinks.configuring` = `guide("configuring")`.
- Produces: `DocLinks.configuring`.
