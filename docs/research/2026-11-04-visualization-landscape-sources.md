## Part A. Tools, one section each

### Sourcetrail (C/C++/Java/Python; desktop; archived)
1. Offline cross-platform source explorer for C, C++, Java, Python; Qt desktop app. Archived read-only 2021-12-14. — https://github.com/CoatiSoftware/Sourcetrail
2. GPL-3.0 (name is a trademark, not covered). — same URL
3. First screen = three linked views (Search, Graph, Code) all reflecting the *currently selected symbol*; the `overview` search keyword shows a project overview. Reads instantly because the graph "focuses on the currently selected symbol and directly shows all incoming and outgoing dependencies". — https://github.com/CoatiSoftware/Sourcetrail/blob/master/DOCUMENTATION.md
4. Node graph centred on one active symbol; edges between the same two groups are **bundled** into one edge with a hover count; classes expand to members with a count on the expander; nodes can be grouped by namespace/package or by file (group nodes). Node/edge colour by kind: types/classes gray, functions/methods yellow, variables/fields blue; edges use the same scheme. Renderer: Qt (not a JS lib). — DOCUMENTATION.md
5. No page-flow view; it has "trails" (call graph, inheritance chain, include tree) and a Custom Trail dialog (To Target / All Referenced / All Referencing) with a **depth slider**.
6. Click node → all views update; click edge → highlights the source location; click a boxed symbol in code → graph re-centres. Legend via `?` / `legend` keyword. Fuzzy search with autocompletion.
7. Sources: README and DOCUMENTATION.md above.

### Emerge / emerge-viz (multi-language; Python + D3 web app)
Note: the task said `teenyicons/emerge` and EmergeTools; the open-source visualiser is **glato/emerge** (PyPI `emerge-viz`). EmergeTools' `emerge` repo 404s; no primary link between the two.
1. "interactive code analysis tool to gather insights about source code structure, metrics, dependencies and complexity"; parses C, C++, Groovy, Java, JavaScript, TypeScript, Kotlin, ObjC, Ruby, Swift, Python, Go. — https://github.com/glato/emerge
2. MIT.
3. Output is a self-contained Bootstrap web app; graphs: file-level dependency graph, entity-level dependency/inheritance/complete graphs, filesystem graph. What it shows first (default graph) is not stated.
4. **Force-directed node graph, D3 simulation rendered on HTML canvas** ("Fast full-screen UI rendering on HTML canvas"); node colour by Louvain cluster with optional cluster hulls; node radius scaled by a metric (e.g. fan-out); "heatmap" of potentially harmful nodes scored by SLOC + fan-out. Also exports GraphML and D3-JSON.
5. No page-flow view.
6. Live search (OR of terms), node select/highlight with keyboard shortcuts, zoom/drag/hover, dark mode; filtering via YAML config (`ignore_dependencies_containing`), not UI.
7. https://github.com/glato/emerge

### Madge (JS; Graphviz)
1. "developer tool for generating a visual graph of your module dependencies"; finds circular deps; AMD/CJS/ESM + Sass/Stylus/Less. — https://github.com/pahen/madge
2. MIT.
3. Static image (SVG/PNG via Graphviz), default layout `dot`, `rankdir: LR`.
4. Static layered diagram; **colour by status**: "Blue has dependencies, green has no dependencies, and red has circular dependencies" (`nodeColor`, `noDependencyColor`, `cyclicNodeColor`). Other engines selectable: neato, fdp, sfdp, twopi, circo. Also `--dot`, `--json`.
5. No page flow.
6. Not interactive; filtering via `--exclude` regex, `--circular`, `--depends`, `--orphans`, `--leaves`, `dependencyFilter`.
7. https://github.com/pahen/madge

### dependency-cruiser (JS/TS; Graphviz / Mermaid / D2 / HTML)
1. Validates and visualises JS/TS/CoffeeScript/LiveScript dependencies against rules. — https://github.com/sverweij/dependency-cruiser
2. MIT.
3. Graph reporters: `dot` (module level), `ddot` ("summarises modules on folder level"), `archi`/`cdot` ("can summarise (or 'collapse') dependencies to folders of your own choosing", default collapse below src/lib/test), `flat`/`fdot` ("all modules on the same level"), `d2` (ELK-capable), `mermaid`, `dot-webpage`. Table reporters: `html` (dependency matrix), `err-html` (standalone report), `metrics` (Ca/Ce/instability per module/folder). — https://github.com/sverweij/dependency-cruiser/blob/main/doc/cli.md
4. Layered static diagram via Graphviz `dot`; `dot-webpage` wraps the SVG in an **interactive HTML page: hover highlights incoming/outgoing deps, click pins the highlight, Esc clears**; `--highlight` for dot-like + mermaid; `--prefix` turns nodes into source links.
5. No page flow.
6. Collapse by folder (`collapsePattern`), rule violations rendered in the graph (colour scheme not described in text), click-to-pin, link-to-source.
7. README + doc/cli.md above.

### Structure101 / Lattix (commercial DSM tools)

### Unreal Blueprints and Blender nodes (node-graph conventions)
- **Blueprints**: "Pins on the left are input pins, while those on the right of the node are outputs"; **execution pins** (order of operations; unwired = outline, wired = solid) vs **data pins** ("type-specific and can be wired to variables of the same type"); "Execution wires are white arrows", data wires coloured "dependent upon the type of data, just as the color of the data pins". — https://dev.epicgames.com/documentation/en-us/unreal-engine/nodes-in-unreal-engine (comment boxes page did not render: **UNVERIFIED**)
- **Blender**: node = title + sockets + properties; "Sockets are input and output values for the node. They appear as little colored circles on either side of the node" (inputs bottom-left, outputs top-right); "Each socket is color-coded depending on what type of data it handles" (Shader bright green, Geometry sea green, Color yellow, Float light gray, Vector dark blue, Object orange); socket **shape** encodes structure (single value, field diamond, grid, list); collapse via toggle or `H`; hide unused sockets `Ctrl-H`. — https://docs.blender.org/manual/en/latest/interface/controls/nodes/parts.html

- **FigJam shapes**: basic (square, ellipse, diamond, rounded rectangle…) and flowchart shapes (parallelograms, cylinder, document, predefined process, manual input, hexagon, Or, summing junction…); colour picker, dashed/solid outlines, bulk colour change. — https://help.figma.com/hc/en-us/articles/1500004414382
- **FigJam connectors**: bent / curved / straight; endpoint styles None/Solid/Line/Triangle/Diamond set per end; text labels draggable along the path with optional background; "Lines snap onto existing shapes and stickies" so connected shapes carry their lines; quick create auto-adds a connector. — https://help.figma.com/hc/en-us/articles/1500004414542
- **Miro user-flow template**: four elements — start/end point, process/action step, decision point ("different branches, and drop-off points"), arrows; "visually differentiate paths (arrows, color, labels)"; split big flows "into sections or phases", "expand or collapse flows as needed". Shapes not prescribed. — https://miro.com/templates/user-flow/

Takeaways for RailsVis (facts, not recommendation):
- Mermaid 12 already ships ELK inside the 5.5 MB vendored file, so a layered layout engine is "paid for". What Mermaid cannot do is drag/rearrange or focus-neighbourhood interaction.
- The cheapest additional path to a draggable node graph is d3-force + d3-drag + d3-zoom (~35 KB min total, ISC, no deps); the cheapest path to a draggable *layered* graph with compound groups and a proven static-HTML story is Cytoscape.js (425 KB, MIT) + cytoscape-fcose (compound-aware force) or cytoscape-dagre (45 KB, layered, bundled dagre) — Nx's `nx graph` is the reference implementation of exactly that stack.
- Mermaid flowcharts also expose `click` bindings and `@{ view: collapsed }` subgraphs, which cover "click node → source" and "collapse group" without a second library.

## Part C. Patterns that recur (with the tools that evidence them)

1. **Entry-point-first.** Sourcetrail centres the graph on the selected symbol and shows only its in/out edges; Nx `--focus <project>`; Azimutt "Find your starting point, then navigate from it: in and out relations"; Android Nav Editor and Storyboards are organised around a start destination / initial controller; Storybook hoists single stories; Starlight/Docusaurus landing pages are a hero + card grid of entry links.
2. **Counts on the overview.** pkg.go.dev "Known importing packages: 1,776,917" and per-domain group counts; Sourcetrail's expander shows how many members are hidden and bundled edges show counts on hover; GitHub Dependents "NUMBER Packages"; Pulse queue card (queued/processing/processed/released/failed); NDepend DSM cells are coupling counts; SchemaSpy anomalies/stats.
3. **Colour by kind or layer, never decorative.** Sourcetrail gray/yellow/blue by symbol kind; Madge blue/green/red by dependency status; cargo-modules by visibility; cargo-depgraph edge colour = dependency kind, dash style = optionality; pyan hue = file, lightness = nesting; Blender/Blueprints socket+wire colour = data type; Swagger UI method badge colours (#61affe get, #49cc90 post, #fca130 put, #f93e3e delete); NDepend green callers / blue callees / red cycles; CodeScene red = low code health.
4. **Method badges + grouping by tag** for endpoint lists (Swagger UI `docExpansion: list`, Redoc tag side-menu / `x-tagGroups`, Scalar `operationsSorter: 'method'`, `operationTitleSource`). Scannability comes from a fixed-width coloured badge in column 1, path in monospace, summary in prose.
5. **Click node → code / details.** Sourcetrail node→code view, edge→source location; Nx node tooltip with project link and "Click on any dependency line to find which file(s) created the dependency"; dependency-cruiser `--prefix` links to repo; NDepend treemap right-click → source; CodeScene click circle → sidebar; Backstage `onNodeClick`; Mermaid `click` binding.
6. **Focus mode / neighbourhood with depth.** Sourcetrail depth slider + trails; Nx focus + proximity; code2flow `--upstream-depth/--downstream-depth`; cargo-modules `--focus-on --max-depth`; Backstage `maxDepth`, `unidirectional`; `mix xref graph --source/--sink`; Azimutt find-path; Nx trace path Start→End.
7. **Collapse by directory / namespace / folder.** dependency-cruiser `archi`/`ddot`/`collapsePattern`; Nx "group by folder" composite nodes expandable in place; NDepend auto cluster nodes + Group-By; Lattix "+" expand on subsystems (hierarchy is why DSMs scale); rails-erd `cluster: true`; graph_models `-g`; pyan `--grouped`; Mermaid `subgraph` + `@{ view: collapsed }`; Storybook `/` title hierarchy; Flutter inspector hides implementation widgets in collapsible groups; Android nested graphs as a single node.
8. **Bundle parallel edges with a count** instead of drawing them all (Sourcetrail), and **trim orphans** by default (code2flow, SchemaSpy lists orphans separately, Madge `--orphans`).
9. **Hover-highlight in/out, click to pin** on an otherwise static SVG (dependency-cruiser `dot-webpage`; NDepend selection colouring). This gives most of the perceived interactivity of a draggable graph without a graph library.
10. **Two synchronised representations of the same data.** NDepend matrix ↔ graph export; Sourcetrail graph ↔ code; dbdiagram code ↔ diagram; Android Design ↔ Text (XML); Flutter device ↔ tree. The user chooses the view that answers the question; selection is shared.
11. **Static-HTML-first producers that still read well**: SchemaSpy (static HTML + Graphviz ER + anomalies), dependency-cruiser `dot-webpage`/`err-html`, emerge (self-contained web app), Turborepo `--graph html`, Jarviz HTML graph, laravel-erd SVG. All ship one file or folder, no server.
12. **Page-flow convention (screens as nodes, actions as labelled arrows, start marked)**: Android Nav Editor (destinations are screen previews, "Actions are represented … as arrows", nested graph = one node), Xcode segues by kind (show/present/popover/unwind), FigJam/Miro (start/end, process, decision, labelled arrows; snap connectors so moved shapes carry their lines). Blueprints/Blender add the convention that **execution flow is white/neutral and data flow is coloured by type**, inputs left, outputs right.
